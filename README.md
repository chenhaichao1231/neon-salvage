# 校园防线 · Campus Defense

**Demo 0.15 · 源码发布版** · [在线试玩](https://chenhaichao1231.github.io/neon-salvage/) · [English](README.en.md)

五行校园塔防。收取 GPU，安排四种 AI 守卫，挡住从右侧进入的数据怪。本说明对应 Demo 0.15 发布源码，在线部署状态需另行核验。

## 开始游戏

1. 选择角色，再点击空格子部署。守卫只向右攻击，先观察各行预告。
2. 悬停或用键盘聚焦可负担的空格子，可预览向右攻击的几何范围。预览不预测命中，也不扣费；确认部署才付款。
3. 准备好后点击“开始入侵”。每 6 战斗秒投放 30 GPU，点击立即领取，不点击则 4 战斗秒后自动到账。
4. 暂停时可以部署、领取现有 GPU、使用紧急撤离。部署立即扣费；未来补给与战斗时间冻结，点击“继续”恢复。
5. “重试本关”精确恢复开战前的布阵、GPU 和随机状态计划，可以重新安排策略。

## 四种基础守卫

四种角色从第一关即可使用，没有新增扩展守卫。角色行为是虚构游戏规则，不是现实 AI 产品评测。

- **DeepSeek · 50 GPU**：低价直射，10 伤害 / 1.1 秒。偶尔在预告后吃饭 2 秒，暂停射击。
- **GPT · 90 GPU**：14 伤害 / 1.4 秒，每发最多穿透两个不同目标。偶尔进入 3 秒弱输出，伤害为 70%。
- **Claude · 120 GPU**：30 伤害 / 2 秒，单体无视装甲。复核前预告 2 秒，然后自动离线 3 秒。复核不问玩家问题、不判断国籍、不读取个人信息。
- **Grok · 80 GPU**：16 伤害 / 1.8 秒，首次命中波及本行 0.8 格内最多三个目标。每第四发变为 4 伤害的“烂输出”，射空也计数。下一发进度与已发弹道质量分别显示。

廉价铺场、穿透、清甲和密集群伤各有用途，不必每关买齐四种角色；昂贵守卫也不保证成功。

## 七个主线关与两个练习

- 前四个主线关分别有 **30、50、54、43 名敌人**，按 **3、4、4、4 段**推进；最后来袭时间为 **55、57.25、68、61 战斗秒**。主线 4“转移的压力”依次考验第 3、5、1 行的补强。
- **主线 5 · 交叠的战线**：53 名敌人，四段从 **4、14、32、52 秒**开始，最后来袭为 **58 秒**。第 2 行重甲与第 4 行集群交叠，随后外侧两行同时受压；中间行较早结束。旧布阵仍可能通过后续补强恢复，不要求特定开局。
- **主线 6 · 交错的追兵**：53 名敌人，四段从 **4、16、36、48 秒**开始，最后来袭为 **58 秒**。第 1、3、5 行装甲与较快的追兵混合，目标先后顺序会自然变化；第 2、4 行后期仍有数据团。最后来袭后仍需清理在场敌人。
- **主线 7 · 轮换的围攻**：54 名敌人，三段从 **4、20、36 秒**开始，最后来袭为 **48 秒**。第 2、3、4 行轮换重甲与密集碎片的压力，第 1、5 行无敌人。为下一轮角色变化预留补给，廉价补强与选择性专长搭配都可行，不要求四种守卫齐上。
- 主线均为普通的五核心生存目标，不要求零漏敌。新关没有新增护盾或共享生命机制。
- 两个可选机制练习分别是 **2 名敌人的一次绕行**、**9 名敌人的合流车队**，要求零漏敌。绕行开始蓄力后，不会因守卫撤离而取消。无需完成练习即可推进主线。

## 经济与操作

准备或战斗中，部署格获得焦点后，单独按方向键可移到相邻格，边缘不换行，也不花费 GPU；暂停时同样可用。Tab / Shift+Tab 保留原有顺序，Enter / 空格键激活当前格。已有守卫或 GPU 不足的格子仍可聚焦。

每关初始 180 GPU，固定补给共 300 GPU，不按击杀额外给钱。早胜不会损失尚未发放的补给。准备阶段全额撤回；每场战斗只有 **一次紧急撤离**，DS / GPT / Claude / Grok 分别退回 25 / 45 / 60 / 40 GPU。

撤离不删除已发出的弹道，重新部署收全价。主动撤离与被击败分开统计，退款不算补给，也不抵扣累计花费。1× / 2× 只改变推进速度；切换到后台自动暂停，返回后需手动继续。

## 显示与进度

主线计划中的敌人全部入场后，若战斗仍在继续，顶部显示剩余在场敌人数；击败和漏敌都会减少该数字。暂停时显示“已暂停”。

时间表中，至少三名敌人的精确等间隔连续来袭显示首尾时间、数量与间隔（或“同时来袭”）。其他事件会中断批次；不规则连续来袭仍逐名显示。

Grok 的普通下一发 **1/4–3/4** 头顶文字只在选中时显示；**下一发 4/4** 警告始终显示。选中详情与无障碍格子标签保留完整信息，其他守卫的真实状态、预警、低生命提示和实际弹道不变。动作与美术保持原样。

未来来袭预告与在场敌人分开显示。相邻敌群有空间时显示类型图形和数量，较窄时只显示总数或省略额外计数；计数不是共享生命或单发命中数。入口与密集状态仍可能重叠；密集碎片的个体生命条可能相互遮叠，显示的敌群数量也不等于整行总数。图片加载失败时使用带提示的备用显示。

战后记录显示本局**首次漏过的敌人类型、行与时刻**，以及 Grok 实际命中至少两个不同目标的发数。这些是战斗事实，不是伤害排名。首次漏敌的类型与逐发命中细节不写入简要历史。

关卡菜单先列七个主线关，再列两个练习。当前版本中实际赢下前一主线关，才能解锁新增的下一关。主线顺序按旧关卡 ID 为 **0→1→2→5→6→7→8→0**，练习路线仍为 **3→4→5**；ID 和书签格式不变。旧练习书签只提供主线 4 的入口；旧主线 4/5/6 的到访或历史结果不能倒推获胜、自动解锁新主线。

存储可用时，语言与可用关卡保存在当前浏览器。刷新在记住的关卡以 180 GPU 空阵重新准备；重试恢复精确开局。每关另存一份上次结束的简要结果，胜败均会替换，不是最佳成绩或奖励，也不恢复战斗。

准备阶段可查看旧结果；条件不同时先显示警告，不计算成绩差值。内容源码版本更新也会保守地将旧有效结果视为历史，加载时不删除、不改写。战斗中隐藏历史，战后只与开战前已显示且条件兼容的结果比较；通关时间只比较两次胜局。“下一关”和刷新可能使用不同随机计划。

结果不跨设备同步。存储失败时新结果仅保留在本次会话；无法识别、损坏或过大的旧记录保持原样。多个标签页以最后成功写入为准。

## 本地运行与检查

浏览器游戏无需后端，可用静态服务器打开仓库根目录；运行游戏不需要 Node.js、`@napi-rs/canvas` 或下面列出的原生字体文件。

测试已在 **Node.js 24.22.1**、**`@napi-rs/canvas` 0.1.100** 及其同版本平台原生二进制包上验证。这是已验证的环境版本，不是最低兼容版本声明。原生画布检查还使用以下硬编码字体路径：

- `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`：Noto Sans CJK collection 2.004。
- `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`：DejaVu Sans Book 2.37。
- `/usr/share/fonts/truetype/noto/NotoSans-Regular.ttf`：Noto Sans Regular 2.004。

这些测试依赖和字体资产不随游戏打包。在其他系统上运行测试前，需提供相同路径的字体文件，或调整测试配置；原样测试不能视为跨平台可用。

```sh
for test in td-*.test.js; do node "$test" || exit 1; done
```
